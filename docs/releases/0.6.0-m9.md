## Controlled runtime decision

The sole M9 network window resolved the exact JVM artifact once and then closed:

| Property | Locked value |
|---|---|
| Coordinate | `org.jetbrains.kotlinx:kotlinx-coroutines-core-jvm:1.11.0` |
| Artifact size | 1,577,052 bytes |
| Artifact SHA-256 | `d1d75aa01dffbb4d1c520e67e4c4e7f5f6174718e7cb4632412503f2f0e604fa` |
| Stable provider asset | `assets/compiler-classpath/kotlinx-coroutines-core-jvm.jar` |
| Compressed APK asset size | 1,446,189 bytes |

The build checks the versioned filename and digest before generating the asset, while the dedicated
controlled configuration is non-transitive. Offline dependency insight confirmed that the release
runtime resolves 1.11.0. Every Gradle gate after the one-time refresh used `--offline`.

The APK defines coroutine core classes including `kotlinx.coroutines.BuildersKt`, `Dispatchers`,
and `CoroutineScope`. It contains exactly one controlled coroutine asset and no
`kotlinx.coroutines.android` definitions or `DebugProbesKt.bin` resource.

M9 deliberately omits `kotlinx-coroutines-android`: the disposable worker has no UI/Looper
contract, so no Main dispatcher is installed. It also omits full `kotlin-reflect` from the script
compiler/D8 surface. Basic stdlib class literals remain supported, while `kotlin.reflect.full.*`,
serialization, coroutine debug/test modules, compiler APIs/plugins, and arbitrary Maven
dependencies remain outside the supported script contract. The complete rationale is in the
[controlled-runtime decision](../decisions/controlled-runtime-libraries.md).

## Fingerprint, cache, and cancellation boundaries

`CompilerClasspath` and `D8RuntimeLibraries` now share the same ordered four-file identity:
class-only Android API 24 stubs, Entry API 2, Kotlin stdlib 2.3.21, and coroutine core 1.11.0. The
compiler-classpath digest domain advanced to v2. Mutating only the coroutine artifact changes the
runtime fingerprint, which changes the toolchain fingerprint; an explicit three-library versus
four-library cache-key cross-test proves that the canonical cache boundary changes too. Old
installed identities fail closed.

The checked-in [`samples/coroutines.kt`](../../samples/coroutines.kt) is read directly by the test
suite, compiled by the real K2 compiler, written to a verified JAR, and converted by D8. Separate
negative compilation proves that full reflect and the Android coroutine module are not exposed.

Host cancellation records the Protocol reason and interrupts the entry thread. The JVM
`runBlocking` contract cancels its structured job on interruption, so `Dispatchers.Default`
children receive cooperative cancellation and the provider preserves `REQUESTED / EXECUTION`.
Uncooperative or unstructured work is still bounded by the existing grace period and mandatory
single-use worker hard-retire; coroutine support does not weaken process isolation.

## Size result

The canonical M8 baseline was 30,384,386 bytes. M9 adds 1,469,880 bytes, or 4.84%, and remains
8,145,734 bytes below the 40 MB decimal release budget. The 1,446,189-byte compressed controlled
asset accounts for nearly all of the increase. Coroutine classes already existed in the APK for
embedded compiler internals, so M9 does not add a second DEX copy of the library.
