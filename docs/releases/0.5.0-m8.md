## Source-shape contract

The current AutoJs6 host continues to submit one Kotlin source normalized to `Main.kt`, with entry
class `<ordinary ASCII package>.Main`. The provider does not hard-code that host profile: it honors
the actual Protocol 1.1 `sourceFileName` and fully qualified `entryClassName` request fields when
they are internally consistent. Both unit tests and the real Binder-path device case executed an
alternative `ScriptEntry` successfully.

M8 made the supported boundary executable and explicit:

- a source of exactly 4 MiB is accepted, while one additional byte returns
  `SOURCE_TOO_LARGE / INPUT`;
- ordinary ASCII package identifiers remain supported, while backtick-escaped and non-ASCII
  package identifiers return the stable public message
  `Kotlin package declarations support only ordinary ASCII identifiers; escaped or non-ASCII identifiers are not supported`;
- a package/request mismatch returns `Kotlin package does not match the requested entry class`;
- multiple top-level classes and a correctly selected alternative entry are accepted, while nested
  same-name, object, interface, abstract, missing-constructor, missing-entry, and ambiguous-entry
  shapes retain deterministic validation outcomes;
- class-file major version 52 remains the maximum accepted script output before D8.

The complete compatibility boundary and prerequisites for any future expansion are recorded in the
[source-layout decision](../decisions/source-layout.md).

## Diagnostic contract

The sanitizer now recognizes the same private source after canonicalization even when K2 and the
provider use different Windows path separators. It still strips every location that does not
canonicalize to that source, preventing compiler internals and private filesystem paths from
crossing the Protocol boundary.

A real K2 compile proves that stripping a leading UTF-8 BOM preserves the user-visible first-line
diagnostic at `Main.kt:1:19`. Complete Protocol diagnostics are measured in encoded UTF-8 and are
truncated only on Unicode code-point boundaries. Chinese text and supplementary emoji regressions
verify that no half surrogate, replacement character, or malformed UTF-8 reaches the wire.

Four checked-in bilingual failure fixtures cover missing imports, type mismatches, a requested entry
that does not implement `AutoJsJvmEntry`, and a package/request mismatch. They are executable test
inputs rather than documentation-only snippets; see the [intentional error samples](../../samples/errors/README.md).
Only predefined, pre-sanitized source-policy messages may override the generic terminal profile.
Arbitrary exception messages, paths, digests, PIDs, and compiler internals continue to use the
existing redaction and stable fallback boundary.

## Toolchain decisions

M8 deliberately retains Kotlin 2.3.21, embedded D8 8.13.17, and script JVM target 1.8. Moving to
target 11 or 17 is not treated as a syntax-only switch: it must first pass class-major validation,
D8/desugaring compatibility, API 26 and API 31 device coverage, cache-identity invalidation, and the
complete release matrix. See the [JVM-target decision](../decisions/jvm-target.md).

Every future Kotlin compiler or D8 change must follow the recorded sequence: update the pinned
coordinate, satisfy the exact Android patch shape, pass the compiler runtime verification, and then
run the complete offline, source-archive, and device gates. See the
[compiler-upgrade SOP](../decisions/kotlin-compiler-upgrade.md).
